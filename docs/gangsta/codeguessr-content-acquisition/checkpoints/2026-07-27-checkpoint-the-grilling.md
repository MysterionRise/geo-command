## Phase A Idea Verdict

**SOUND.** The objective is a bounded acquisition pipeline for licensed GitHub code that can create:

- language-mode review drafts from licensed, immutable code changes; and
- provenance-mode review drafts only when vendor-documented commit attribution or verified agent/bot authorship records model participation.

The public claim is never AI detection and never exclusive authorship. Missing attribution is not evidence of human-only authorship; negative provenance examples still require project-controlled affirmative evidence.

## Grilling Conclusions

### Idea Verdict

**SOUND.** The pipeline may acquire language candidates and narrowly evidenced positive provenance candidates from licensed, immutable GitHub changes. Provenance asks whether an AI coding agent is durably recorded as participating; a named-model claim is permitted only when the accepted record names that model. Missing attribution never establishes human authorship.

### Key Decisions

1. Use an offline operator command, not a gameplay-time crawler.
2. Require an exact allowlisted repository, approved subtree, full commit SHA, frozen license policy and frozen attribution-marker policy.
3. Treat license metadata only as admission screening; independent review decides file coverage, notices and attribution timing.
4. Reconstruct provenance changes from pinned parent and child blobs; GitHub's displayed patch is diagnostic only.
5. Accept only vendor-documented markers, verified agent/bot authorship or vendor session evidence; arbitrary claims are rejected.
6. Preserve `NAMED_MODEL_RECORDED` separately from `AGENT_RECORDED`; never infer exclusive authorship or AI detection.
7. Emit only immutable `DRAFT_REVIEW_REQUIRED` artifacts with policy hashes, source hashes and explicit non-publishable state.
8. Traverse approved immutable subtrees with resumable, hash-verified checkpoints.
9. Store raw snapshots outside the repository using encrypted-at-rest, atomic, no-follow private storage and explicit deletion/retention.
10. Keep acquisition behind an operator-only package subpath and prove it is absent from browser/game dependency graphs.
11. Require one independently reviewed, non-public draft-to-playable rehearsal for language and one for recorded-agent participation.
12. Amend and sign the programme and child Contract before implementation.

### Rejected Alternatives

- General web or repository crawling — rejected for rights, scope and API-control risk.
- Stack Overflow ingestion — remains excluded.
- Public GitHub visibility as sufficient permission — rejected; an applicable license and item review are required.
- Absence of an AI marker as human evidence — rejected as logically invalid.
- Style-based AI detection or exclusive-authorship claims — rejected as unsupported.
- Trusting commit-page patches as complete evidence — rejected in favour of parent/child blob reconstruction.
- Automatic eligibility or publication — rejected; acquisition ends in quarantine.
- Repository-local raw storage — rejected due containment and accidental-packaging risk.
- A language-only pipeline — superseded by narrowly evidenced recorded-agent participation.

### Unresolved Objections

None critical. Exact schema field names, numeric limits, retention mechanics, policy signatures and acceptance wording remain specification work for The Sit-Down, not unresolved product decisions.
