## Findings adopted for Revision 6

2. **B-002 — Delivery structure.** Treat the Contract as a programme charter with six child Heists: content/evidence, arcade/state, provenance, language, enrollment/privacy, and beta measurement/operations.
3. **B-003 — Manifest semantics.** Replace one-manifest-per-day language with one lineage per day, multiple immutable correction versions, and one version eligible for new issuance at a time.
4. **B-004 — Lifecycle definitions.** Define ISSUED and DISPLAYED; use authoritative ISSUED state for replacement eligibility.
5. **B-005 — Orthogonal state.** Separate session, interaction, correction, clue, and accepted-answer state.
6. **B-006 — Stack Overflow rights gate.** Require a Don-approved written determination before eligibility and use project-owned human samples as the fallback.
7. **B-007 — Model-output rights.** Record provider terms, account/plan, commercial-use basis, data-use setting, restrictions, similarity review, third-party-rights decision, and approved disclosure.
8. **B-008 — Source durability.** Resolve citations through exact artifact paths and immutable content hashes with stable decision IDs.
9. **B-009 — Risk controls.** Give each risk likelihood, owner, mitigation, trigger, contingency, residual risk, and Don acceptance.
10. **B-010 — UTC lifecycle.** Use midnight UTC and half-open daily intervals consistently.
11. **B-011 — Streak wording.** Calculate streaks only from authoritative UTC completion while localizing display only.
12. **B-012 — Reviewer independence.** Add a compatibility matrix and minimum staffing model.
13. **B-013 — Measurement contracts.** Freeze event types/fields, scoring shape, clue penalties, candidate handling, denominators, inclusion transitions, formula inputs, and versioning before Resource Development; leave only thresholds and final survey wording to signed release artifacts.
14. **B-014 — Browser boundary.** Define supported browsers, minimum viewport, JavaScript fallback, and assistive-technology combinations.
15. **B-015 — Performance boundary.** Add measurable shell, mutation, rendering, and idempotency targets.
